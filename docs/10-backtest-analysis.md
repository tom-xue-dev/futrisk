> 题目的附加项要求"支持用历史数据回放验证风控规则的有效性"。本文说明回测怎么做、数据从哪里来、结果是什么，以及这些结果能说明什么、不能说明什么。先给结论：验收场景在生产的风控内核上被精确复现（16 项断言全部通过）；2015 年以来的日线回放中，日亏规则在 100 个账户日生效，触发时点符合规则定义；但对一个每天只在均线交叉时开仓的双均线策略，"熔断禁开"只在 5 个账户日改变了当天的盈亏，11.7 年合计只差 0.07 个百分点——**熔断禁开挡的是亏损之后的新开仓，策略越少在亏损日开仓，它的作用越小**。这是以合成日内路径为条件的结论。

## 1. 要回答的问题

1. 验收场景（ACC3 单日亏损达到初始资金的 3% 时熔断禁开）在回放中能否被精确复现，包括只告警一次、锁存、坏点不锁存；
2. 按 04 定义的日亏规则（−2% 告警、−2.5% 限制下单、−3% 熔断禁开、−5% 生成减仓计划）在历史行情上会不会触发、在什么时候触发；
3. 触发之后，规则对策略的盈亏有什么影响。

## 2. 方法

### 2.1 同一个风控内核
回测不启动任何服务：同一个 `EngineCore` 加进程内总线 `InprocBus`、进程内柜台和同一个 `settle_day`（01 §8.16）。因此回测里的告警状态机、事前检查、熔断确认与锁存、逐日盯市结算，与生产代码完全相同；与生产不同的只有数据来源（历史数据代替行情网关）和成交方式（按价格点成交，无滑点、无部分成交）。每天收盘后还会用 `core.freeze` 的成交摘要与进程内柜台的成交核对，结算的全部对账检查也照常执行。

### 2.2 配对实验
两个方案（arm）用相同的数据和相同的策略回放，只有规则不同，所以两个方案的差值只来自规则本身：

| 方案 | 档位 | 规则 |
|---|---|---|
| `no_rules` | `none` | 不启用规则（事前检查中的静态、资金、交易时段等检查照常） |
| `block_open` | `block_open` | 生产的日亏规则：−2% 告警，−2.5% 限制下单（单笔上限减半、禁止在亏损品种加仓），−3% 熔断（立即禁开，确认后锁存），−5% 生成减仓计划 |

熔断阈值可以用 `rules.threshold` 整体缩放（四个级别按 2/3、5/6、1、5/3 的倍数一起移动）。

### 2.3 账户与策略
5 个演示账户（`accounts.yaml`）各自交易自己的品种，都用同一个双均线策略 `dual_ma`：

| 账户 | 初始资金 | 品种 |
|---|---|---|
| ACC1 | 1000 万 | rb、hc、i、j |
| ACC2 | 2000 万 | rb、cu、au、m、IF、T |
| ACC3 | 1000 万 | rb、hc、i |
| ACC4 | 1000 万 | IF、IC |
| ACC5 | 500 万 | rb |

- **信号**：每个品种的 5 日与 20 日简单均线（日收盘价，换月时按新旧合约的结算价之比向后复权）。在**每个行情状态**上，用最新价代替当天的收盘价计算两条均线：快线高于慢线 0.2% 以上做多，低于 0.2% 以上做空，其间保持原方向；
- **仓位**：每个品种的目标名义金额为初始资金的 15%，并且不超过该品种敞口上限（权益 × 3% ÷ 涨跌停幅度）的 85%；按初始资金而不是当前权益定仓位，所以两个方案每次调仓后持有同样大小的头寸，差值不会因为头寸大小逐渐漂移而放大；
- **执行**：目标仓位由执行器变成委托，经过同一条事前检查；SHFE 先平昨、再平今，最后开新方向；持仓始终在当天的主力合约上，换月日平旧开新；
- 策略在 2015-01-05 之前用 40 个交易日的历史预热，不交易。

这个策略是占位：它的作用是让委托像真实策略一样经过风控内核，而不是作为收益来源来评价。

### 2.4 日内路径
A 层只有日线，日内路径按"开盘价靠近哪个极值就先走哪个"合成：开 → 近端极值 → 远端极值 → 收，四个锚点分别放在交易时间的 0、1/3、2/3 和 1 处，每段至少 4 个价格点，一段的涨跌幅超过开盘价的 0.25% 时加密，保证亏损是逐步越过阈值，而不是一步跳过。同一时段的合约同时到达各自的极值（同步、偏悲观）。一个日线对应很多条可能的日内路径，所以 A 层的结果都是**在这个路径模型下**的结果。

### 2.5 统计
- **收益**：日盈亏之和 ÷ 初始资金（按初始资金定仓位，所以收益可以直接相加）；**最大回撤**：权益（初始资金 + 累计盈亏）相对其历史高点的最大回落；**最差单日**：日盈亏 ÷ 初始资金的最小值；
- **规则生效日**：`block_open` 方案中触发了限制下单或熔断级别的账户日；
- **当日效果**：生效日当天 `block_open` 与 `no_rules` 的日盈亏之差 ÷ 初始资金，正数表示规则让这个账户少亏（或多赚）；**次日效果**：生效日下一个交易日的同样差值（锁存在换日时解除，次日效果反映的是被挡住的开仓推迟一天之后的结果）。一个生效日的次日可能本身也是生效日，所以两个合计不能相加。

## 3. 数据

| 层 | 内容 | 来源 |
|---|---|---|
| A | 10 个品种（rb、hc、cu、au、i、j、m、IF、IC、T）2015-01-05 至 2026-09-24 的逐合约日线和官方结算价，共 2852 个交易日 | `data/hist/daily/`，获取方法和校验见 `data/hist/SOURCES.md` |
| D | 合成剧本：给定参考价、持仓、价格步骤和脚本委托，每一步的正确结果已知 | `config/backtest/breaker_synthetic.yaml` |

- 持仓始终在主力合约上，主力合约取自连续序列（`daily/{product}.parquet`）；换月日在旧合约上平仓、在新合约上开仓，旧合约当天的走势来自逐合约数据；
- 结算用官方结算价。DCE 2024-07-17 之后只有主力合约的数据，缺失的非主力结算价用 (最高 + 最低) ÷ 2 按最小变动价位取整估计，缺数据的旧主力在换月日按昨结算价平出，这些账户日在 `daily.csv` 中标为 `est_settle`；
- 回测读取的每个数据文件都在读取时计算 SHA-256，并与 `data/hist/manifest.json` 核对（本次 20 个文件，全部一致），写进运行清单。

## 4. 结果

### 4.1 验收场景的精确复现（D 层）
`breaker_synthetic` 的两个剧本在 `block_open` 方案上的 16 项断言全部通过，`no_rules` 方案没有产生任何风险事件：

| 剧本 | 过程 | 结果 |
|---|---|---|
| `acceptance_breaker` | ACC3 持有约 0.77 倍权益的黑色多头；板块依次下跌 2.7%、3.3%、4.0%、4.05% | s1 告警（日亏 −2.09%）、s2 限制下单（−2.55%），此后加仓被拒 `REJECT_ADD_TO_LOSER`；s4 首次越过 −3% 立即进入 HALTED（未锁存），s5 第二个行情状态确认并锁存（−3.14%），全程只有一条熔断告警；锁存后开仓被拒 `REJECT_ACCOUNT_HALTED`，平仓成交；价格回升到 −3.5% 时锁存保持 |
| `single_bad_tick` | 同样的持仓，rb 单独打出一笔 −9% 的坏价，300 毫秒后回到原位 | 熔断只进入待确认（HALTED，未锁存），下一个状态即撤销，没有熔断告警；之后开仓照常成交 |

报告：[docs/backtests/breaker_synthetic.html](backtests/breaker_synthetic.html)。

### 4.2 历史回放的主要结果（A 层）
`default` 配置，2015-01-05 至 2026-09-24，2852 个交易日。两个方案的全部 2852 个交易日结算对账全部通过，成交摘要核对不一致 0 次。

|---|---:|---:|---:|---:|---|---:|
| ACC1 | 90.00% | 9.55% | 90.57% | 9.44% | 121 / 57 / 37 | 3 |
| ACC2 | 36.45% | 10.10% | 36.45% | 10.10% | 10 / 3 / 1 | 0 |
| ACC3 | 57.16% | 11.29% | 56.98% | 11.31% | 63 / 34 / 19 | 1 |
| ACC4 | 10.21% | 15.89% | 10.21% | 15.89% | 9 / 6 / 1 | 0 |
| ACC5 | 17.33% | 5.49% | 17.33% | 5.49% | 0 / 0 / 0 | 0 |
| 合计 | 43.44% | 7.81% | 43.51% | 7.83% | 139 / 71 / 40 | 4 |

### 4.3 效果来自哪里
规则在 100 个账户日生效（其中 58 个熔断锁存），但**只有 5 个账户日的当天盈亏因此改变**：

| 交易日 | 账户 | 级别 | 规则前后的当日盈亏 | 当日效果 | 发生了什么 |
|---|---|---|---|---:|---|
| 2016-11-30 | ACC1 | 熔断 | −4.23% → −3.92% | +0.31pp | 换月日：锁存后平掉旧主力 hc1701，在新主力 hc1705 上重新开仓被拒，当天剩余时间空仓 |
| 2020-02-03 | ACC3 | 熔断 | −3.91% → −3.70% | +0.22pp | 节后跌停日：锁存后均线翻空，平掉多头，开空被拒 |
| 2020-02-04 | ACC3 | 限制 | −1.48% → −1.87% | −0.39pp | 前一天被挡住的空单推迟到今天开盘才开出，错过了隔夜的跌幅 |
| 2020-03-19 | ACC1 | 熔断 | −2.73% → −2.20% | +0.53pp | 锁存后均线翻空，平仓成交、开空被拒 |
| 2021-06-21 | ACC1 | 熔断 | −2.31% → −2.06% | +0.25pp | 同 2020-03-19 |

当日效果合计 +0.91pp（4 天少亏、1 天多亏），次日效果合计 −0.61pp：锁存在换日时解除，被挡住的开仓在下一个交易日开盘时照样发生，只是推迟了一天，价格有时更好、有时更差。其余 95 个生效日当天盈亏完全相同，原因是：

1. **熔断禁开挡的是新开仓**。双均线只在两条均线交叉时换方向，大多数亏损日它只是继续持有原来的仓位，没有要开的仓；熔断撤销的也只是开仓挂单，而这个策略按价格点立即成交，没有挂单可撤。例外是锁存后反手（2020-02-03 等 3 天）和锁存当天恰好换月（2016-11-30）：换月时在新合约上重新开仓同样算开仓，会被挡住，这个品种当天就空仓了；
2. **合成路径先走到极值、再回到收盘价**。很多触发日的盘中最低点越过了 −3%，收盘却回到 −2% 左右（例如 2016-03-09 ACC1 盘中 −3.01% 锁存、收盘 −1.75%）；锁存本身不改变持仓，所以这些日子两个方案的盈亏一样。

所以，对这类只在信号变化时开仓、不在亏损中加仓的策略，熔断禁开几乎不改变历史收益和回撤（合计收益 +0.07pp、最大回撤 +0.02pp、最差单日 +0.06pp）。它真正起作用的场景是**亏损中继续开仓**：翻向另一个方向、逆势加仓、重新建仓。这一点由 D 层剧本（锁存后开仓被拒、平仓成交）和单元测试（`tests/unit/backtest/test_bt_strategy.py`：锁存后均线翻空，平仓成交、开空被拒；`test_bt_review.py`：一个逐级加仓的策略，加仓被挡住后两个方案的盈亏不同，而不加仓的静态持仓两个方案完全相同）精确验证。

## 5. 结论与局限

**结论**：
- 规则在生产的风控内核上按定义工作：告警、限制下单、熔断按阈值依次触发，熔断立即禁开、确认后锁存、只告警一次，单个坏点不会锁存（§4.1）；
- 在 2015 年以来的历史行情上，规则在大波动时期按预期频繁触发（§4.2）；
- 规则对收益的影响取决于策略在亏损日是否开仓：对本回测的双均线策略几乎没有影响，对亏损中加仓或反手的策略则会直接挡住这些开仓（§4.3）。**3% 是题目给定的阈值，回测没有对它做优化**；
- 回测发现了一处规则语义上的缺口：熔断禁开不区分"换月时在新合约上重新开仓"和真正的新开仓，锁存当天如果恰好换月，这个品种会被迫空仓到下一个交易日（2016-11-30）。生产中如果希望锁存期间照常换月，需要为换月单单独放行（01 TD-17）。

**局限**：
- A 层的日内路径是合成的（§2.4），触发时点和"盘中越线、收盘回落"的情形都依赖这个路径模型；真实的日内路径需要分钟线或 tick；
- 成交按价格点，没有滑点、没有部分成交；封板时不成交；
- 双均线只是占位策略，它的收益不代表任何实际策略；
- 精简版只比较"无规则"与"生产规则"两个方案。完整版（git 标签 `v0.1-full`）还有随机路径集合、分钟线对照、安慰剂与减仓档位、阈值扫描和自助法置信区间，它的结论与本文一致：规则的效果主要来自拦住逆势加仓，对不加仓的持仓几乎没有作用。

## 6. 如何复现

```powershell
futrisk backtest run breaker_synthetic        # D 层剧本，约 1 秒；检查不通过时退出码为 2
futrisk backtest run default                  # A 层全期，两个方案并行约 2 分钟
futrisk backtest run default --set start=20161101 --set end=20161130   # 只跑一个窗口
futrisk backtest run default --set rules.threshold=0.02                # 换一个熔断阈值
futrisk backtest show <运行目录>               # 清单和摘要
```

每次运行的输出在 `<home>\backtests\<名字>-<时间戳>\`：`report.html`（自包含报告）、`daily.csv`（每个方案、账户、交易日一行）、`events.csv`、`orders.csv`、`summary.json` 和 `manifest.json`（配置哈希、数据哈希、git SHA、代码哈希）。回放是确定性的：同样的配置和数据，进程数不同，结果和事件哈希也相同。本文的数字来自提交 `48a473d` 上的一次运行（配置哈希 `b547f84f3cec56e6`，数据哈希 `0c14dfda98cd8da2`，用时 125 秒）。
